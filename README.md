# Firefox-style PiP для Brave

Модификация **встроенного видео-PiP** в Brave для Windows x64 и macOS.
Проект содержит патч и команды подготовки. Исходники Brave и Chromium
скачиваются отдельно и не попадают в этот Git-репозиторий.

**Статус сборки и проверок: [STATUS.md](STATUS.md).**
Это экспериментальная сборка на закреплённом Brave 1.97.16 / Chromium
153.0.8010.28. Она не меняет установленный Google Chrome.

## Что меняется

- Кнопки воспроизведения и перемотки по центру; дополнительные кнопки
  предыдущего/следующего трека сохраняются, если сайт их предоставляет.
- Таймлайн во всю ширину окна, время под ним, mute слева.
- Кнопки возврата во вкладку и закрытия сверху; заголовок не заходит под них.
- Минимальный размер 320 × 180; увеличение до рабочей области экрана.
- `Space` — play/pause, если фокус не на отдельной кнопке. `K` — play/pause.
- `←` / `→` — ±10 секунд; `Home` / `End` — начало/конец.
  У сфокусированных контролов сохраняется их штатная обработка клавиш.
- `M` — mute. `F` — развернуть в рабочую область / вернуть размер.
  `Esc` возвращает размер развёрнутого окна.
- Перемотка отключена для неизвестной и бесконечной длительности.

`F` увеличивает обычное окно PiP; это не системный fullscreen с отдельным
рабочим столом macOS. Сохраняются штатные видео, звук и обработка DRM.
Ползунок громкости, перенос субтитров сайта и несколько одновременных PiP
в эту версию не входят. Кнопка Live Caption остаётся штатной функцией Chromium.

## Windows: подготовить один раз

Используйте короткий путь без пробелов, например `C:\firefox-pip`.
Нужны Windows 10/11 x64 и включённый **Developer Mode**.

Установите:

1. Git for Windows 2.41+.
2. Python 3.9+ с launcher `py`.
3. Node.js **24.x, начиная с 24.16.0**.
4. pnpm **11.19.0**: `npm install -g pnpm@11.19.0`.
5. Visual Studio **2026, 18.0.0+**, компонент **Desktop development with C++**,
   включая **MFC/ATL для x64/x86**.
6. Windows SDK **10.0.28000.2270** и SDK Debugging Tools **10.0.26100.3323+**.

Версии Visual Studio/SDK взяты из
[инструкции закреплённого Chromium](https://chromium.googlesource.com/chromium/src/+/153.0.8010.28/docs/windows_build_instructions.md).
Общая wiki Brave может описывать другой toolchain.
Официальный минимум диска — 100 ГБ; для исходников, зависимостей и нескольких
конфигураций сборки лучше иметь заметный запас. Первый запуск скачивает много
данных и может занимать часы вместе с компиляцией.

После установки откройте новое окно **cmd.exe** в папке проекта:

```bat
build.cmd doctor
build.cmd bootstrap
build.cmd build
build.cmd run
```

`bootstrap` скачивает закреплённые исходники и применяет штатные патчи Brave.
`build` применяет наш PiP-патч и выполняет инкрементальную Component-сборку.
`run` запускает браузер с отдельным профилем `.build\profiles\pip-test`.
Передача вручную одного `brave.exe` с Component-сборки недостаточна:
рядом нужны её DLL и ресурсы.

Для установщика и архивов:

```bat
build.cmd package
```

Эта команда собирает конфигурацию Static и штатную цель `create_dist`.
Ожидаемый установщик:
`.build\src\out\PipStatic-x64\brave_installer.exe`.
Архивы лежат в `.build\src\out\PipStatic-x64\dist`.
Подпись издателя отключена; сертификат для личной сборки не нужен.
Канал — Nightly. Автообновление браузера отключено, чтобы обычный upstream
не заменил модификацию. Обновления исходников и безопасности нужно собирать заново.

## macOS

Нужны полный Xcode, Git, Python 3.9+, Node и pnpm указанных выше версий.
На Apple Silicon автоматически выбирается arm64.

```sh
./build.sh doctor
./build.sh bootstrap
./build.sh build
./build.sh run
```

На каждом компьютере своя папка сборки. Через Git переносятся только этот
проект и патч; объекты компиляции между Windows и macOS не переносятся.

## Параметры и повторные сборки

```bat
build.cmd bootstrap --build-root D:\pip-build
build.cmd build --build-root D:\pip-build --jobs 8
build.cmd run --build-root D:\pip-build
build.cmd package --build-root D:\pip-build --jobs 8
```

Во всех командах используйте одинаковый `--build-root`, если изменили его.
По умолчанию используются шесть параллельных задач и локальная сборка без
платного сервера компиляции.

После первого успешного `bootstrap` достаточно повторять `build`.
После обрыва первоначальной загрузки можно повторить `bootstrap`: уже скачанные
данные сохраняются. Эта команда откажется работать, если в brave-core уже есть
изменения отслеживаемых файлов. Она не сбрасывает пользовательские правки.

Для сравнения до применения PiP-патча доступна неизменённая сборка:

```bat
build.cmd bootstrap
build.cmd build --baseline
```

Последующая команда `build.cmd build` использует ту же папку объектов:
после применения патча повторно компилируются затронутые части.

Логи каждой команды находятся в `<build-root>/logs`.
Если команда завершилась ошибкой, изучите первую содержательную ошибку в логе.
`bootstrap.json` появляется только после успешной полной подготовки;
наличие скачанной папки `src` само по себе не означает готовность к компиляции.

## Проверки

Быстрые проверки команд подготовки, защиты пользовательских правок и точечного
исправления зависимости:

```bat
py -3 -m unittest discover -s tests -v
```

Нативные тесты PiP (требуют законченной подготовки и компиляции):

```bat
build.cmd test
```

Для проверки вручную откройте `fixtures/pip.html` в нашей сборке и выберите
локальный видеофайл. Проверьте таймлайн, mute, фокус через Tab, разворот,
возврат во вкладку и закрытие. Затем проверьте YouTube и используемые вами
сайты: доступность перемотки и других действий зависит также от плеера.
На Windows дополнительно проверьте мониторы с разным масштабом, перенос окна
между ними и поведение поверх других приложений.

## Как устроен проект

- `upstream.json` — точный коммит Brave; версия Chromium определяется им.
- `patches/firefox-pip.patch` — изменения C++, нативные тесты и подключение тестов.
- `pip_build.py` — подготовка, применение патча, сборка и запуск.
- `scripts/pnpm_compat.py` — исправляет только правило сборки закреплённого
  `figma-api-exporter` во временной копии Leo. Перед изменением сверяет
  исходную конфигурацию и ревизию зависимости. Общие настройки pnpm не меняются.

При разработке можно редактировать `<build-root>/src/brave` и вызывать там
штатный `pnpm run build` с теми же параметрами. Для переноса новых изменений
обновите патч в этом репозитории; исходники из игнорируемой `.build` сами
по себе не попадут в Git. Не меняйте коммит в `upstream.json` без проверки
патча, зависимостей и toolchain на новой версии.
